# MDU Passport — Design Plan

## Overview

MDU Passport is a clean-slate replacement for the existing mdu-tracker (Django monolith on a local server). It's a property management + common area WiFi configurator for Hawaiian Telcom's MDU/resort deployments.

**Stack:** Next.js (App Router) + Supabase + Vercel + GitHub
**Why new repo:** mdu-tracker is Django 4.2.7 + SQLite, server-hosted, full of cruft (Vitruvi checklists, OLT platform tracking, fiber port fields). Jay wants durable cloud infrastructure — code on GitHub, frontend on Vercel, data on Supabase.

## Core Features

### 1. Property Record
- Create/edit properties (name, slug, type, address, island, GM name, GM email, notes)
- Property types: MDU, resort, office, mixed
- Properties already seeded in the property-scan Supabase project (`ynaexnssjefpayxnvdzi`) — reuse or mirror that table

### 2. Property Passport (Markdown Import)
- Import a markdown file generated by the property-scan skill (from walkthrough sightings)
- Parse and render: header (property, date, scan summary), per-location breakdown with device inventory
- Store the markdown + rendered view per property
- Display sighting photos via Supabase Storage signed URLs

### 3. Property Scan Integration
- Read from the property-scan Supabase project (`ynaexnssjefpayxnvdzi`)
- Tables: `properties`, `property_scan_sessions`, `property_scans`, `property_type_checklists`
- Storage bucket: `property-scans` (photos from walkthroughs)
- When a scan session exists for a property, show sightings grouped by location with photos + narration + extracted device data

### 4. Common Area Configurator (Ported from mdu-tracker)
- Manage common area WiFi/fiber installation planning for shared property spaces
- Area types: pool, gym/fitness, lobby, hallway, courtyard, parking, office, other
- Per area: name, description, installation status (not_started/in_progress/completed), priority (1-5), installation date
- Equipment list per area with quantities (dynamic rows — add/remove equipment)
- Equipment master table (reusable across properties): name, type, model, manufacturer, description
- Dashboard: status counts per property (x completed, y in progress, z total)

### 5. Property Notes
- Free-text notes attached to a property
- Timestamped, attributed to user
- Searchable

### 6. PDF Export
- Generate a Property Passport PDF per property
- Includes: header, common area summary, equipment inventory, sighting photos, notes
- Downloadable from the UI

## Data Architecture

### Option A: Single Supabase Project (Recommended)
Use the existing property-scan project (`ynaexnssjefpayxnvdzi`) and add new tables for common areas + equipment. Avoids cross-project queries.

### Option B: Separate Supabase Project
New project for MDU Passport, read from property-scan project via API. More isolation but more complexity.

**Recommendation:** Option A — add tables to `ynaexnssjefpayxnvdzi`.

### Tables to Create (new)

```sql
-- Equipment master catalog
CREATE TABLE equipment_types (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id uuid NOT NULL,
  name text NOT NULL,
  category text, -- 'ap', 'switch', 'router', 'ont', 'cable', 'mount', 'other'
  manufacturer text,
  model text,
  description text,
  created_at timestamptz NOT NULL DEFAULT now()
);

-- Common areas per property
CREATE TABLE common_areas (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id uuid NOT NULL,
  property_id uuid NOT NULL REFERENCES properties(id) ON DELETE CASCADE,
  area_type text NOT NULL, -- 'pool', 'gym', 'lobby', 'hallway', 'courtyard', 'parking', 'office', 'other'
  area_name text NOT NULL,
  description text,
  notes text,
  installation_status text NOT NULL DEFAULT 'not_started', -- 'not_started', 'in_progress', 'completed'
  priority integer DEFAULT 3 CHECK (priority BETWEEN 1 AND 5),
  installation_date date,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX idx_common_areas_property ON common_areas(property_id);

-- Equipment assigned to common areas
CREATE TABLE common_area_equipment (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id uuid NOT NULL,
  common_area_id uuid NOT NULL REFERENCES common_areas(id) ON DELETE CASCADE,
  equipment_type_id uuid NOT NULL REFERENCES equipment_types(id),
  quantity integer NOT NULL DEFAULT 1,
  notes text,
  created_at timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX idx_cae_common_area ON common_area_equipment(common_area_id);

-- Property notes
CREATE TABLE property_notes (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id uuid NOT NULL,
  property_id uuid NOT NULL REFERENCES properties(id) ON DELETE CASCADE,
  content text NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX idx_property_notes_property ON property_notes(property_id);
```

### Existing Tables (already in ynaexnssjefpayxnvdzi)

- `properties` — property registry (name, slug, type, island, GM info)
- `property_scan_sessions` — one row per walkthrough
- `property_scans` — one row per sighting (device type, model, SN, MAC, photo URLs, narration)
- `property_type_checklists` — expected locations per property type

## What to Port from mdu-tracker

**Port (adapt to Next.js + Supabase):**
- Common area data model (CommonArea + CommonAreaEquipment)
- Equipment type catalog (EquipmentType)
- Dynamic equipment formset pattern (Django inlineformset → React hook-form with dynamic rows)
- CSV import/export for bulk loading
- PDF export with property + common area aggregation

**Leave behind:**
- `jays_notes` JSONField (replace with property_notes table)
- `fiber_ports_*` fields (3 port count fields for discrepancy tracking)
- `current_platform`, `required_platform`, `clli` (OLT platform tracking)
- Vitruvi-specific checklists (`wiring_plan_uploaded_vitruvi`, `property_created_vitruvi`, `prs_verified`)
- Document OCR/parsing pipeline
- MilestoneTemplate, Task, DailyProgressLog (installation progress tracking)
- Django auth system (replaced by Supabase Auth)
